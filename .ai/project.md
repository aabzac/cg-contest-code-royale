# Настройки конкретного контеста

Этот файл — редактируемый источник правил проекта. Заполните неизвестные поля
по репозиторию и официальным условиям игры. Значение «не задано» не является
командой и не разрешает агенту выдумывать её. После изменений выполните синхронизацию.

Печатается и config id — первые 8 hex sha256 кода от `class Player {` до секции раннера (без заголовка импортов, куда попадают и импорты раннера) плюс значение PARAMS как написано (`Build.config`): сборки, различающиеся только раннером (например, меткой), имеют общий config id; по-разному записанные параметры (`""` и умолчания явно) — разные. Артефакт печатает build id на ходу 0 (строка «Метка сборки в реплее») |

Сначала печатаются sha256, PARAMS, build id (сверяется с содержимым) и config id проверяемого артефакта. Каждая игра повторяется с in-process `current` и PARAMS артефакта; строки команд обеих сторон обязаны совпасть (`sameAsCurrent` по всем играм), кроме метки: на ходу 0 артефакт обязан напечатать ровно свою метку там, где у `current` пустой TRAIN. Игра, где соперник снят (таймаут или неверный вывод) хотя бы в одном из двух прогонов, не сравнивается и проваливает проверку (`notCompared`; `minTurns` показывает самую короткую игру). Провал также при лишних строках stdout и любых строках stderr, кроме `SLOW turn`; строки, пришедшие после пропущенного дедлайна, считаются отдельно (`lateLines`). Код выхода 1 при любом провале. При таймауте печатается команда повтора для seed с теми же `-Pparams`. После пропущенного дедлайна артефакт получает 2 s, чтобы дописать ответ и SLOW-отчёт; не успевший убивается, и заметка говорит «no conclusion». Провал только из-за таймаута, когда артефакт доработал до конца без SLOW-отчёта (задержка вне его собственного хода; на ходу 0 его часы стартуют с первого токена ввода, после запуска JVM и init), перечитывается после тихого повтора названных seed, записываются оба результата. Процессы запускаются без JDK_JAVA_OPTIONS, JAVA_TOOL_OPTIONS и _JAVA_OPTIONS (в любом регистре). Проверка показывает, что упаковка не меняет игру исходного бота на достигнутых позициях; логику бота она не проверяет |

## Сравнение версий

Политика P2 от 2026-10-30, подробно — `docs/local-screen.md`.

- Базовая версия (контроль): версия, которую заменяет кандидат, то есть локальный чемпион — последняя версия, прошедшая P2 (какая сейчас — `docs/STATUS.md`; класс `cr.bot.vNN.GreedyBot`, снимок параметров `src/main/resources/cr/bot/versions/vNN.properties`). Кандидат — `current` со своим флагом, остальные флаги выключены.
- Набор соперников (P2, проверка PV1 от 2026-10-30):
  - прямой матч с контролем;
  - `boss` — Default AI из referee-репозитория (один барак рыцарей, без уклонения; v01 выигрывает у него 95 %); это только нижняя планка, не модель Princess Boss;
  - `old` — код записи 3315948 (19.64), запуск внешним процессом из `refs/old-3315948/Player.java` (вне Git, файл кладёт пользователь; пока его нет).
  Внешние процессы запускаются с `-Pthreads=3 -PturnMs=200`, серии внутри процесса — с `-Pthreads=8 -PturnMs=50`.
- Seed для разработки: все seed < 200000 (включая уже использованные) и фикстуры.
- Отдельный набор для итоговой оценки:
  - скрин — свежий блок `200000 + 2000·k` из 2000 карт на кандидата (внешние соперники играют первые 500 карт блока);
  - итоговая оценка перед загрузкой — блок `400000 + 2000·k`, один раз;
  - реестр блоков — `docs/data/seed-ledger.json`.
- Перестановки сторон / мест и политика случайности: каждая карта (`MapGen`, `java.util.Random(seed)`) играется дважды с обменом мест свежими ботами. SEED ботов = 1, все боты детерминированы, поэтому повторный прогон тех же seed новых данных не даёт.
- Основная метрика и критерий принятия изменения:
  - метрика — S, счёт по картам (2 игры, ничья = ½), 95 % CI по картам (`± 1.96·SD/√карт`);
  - против общих соперников — Δ = S(кандидат) − S(контроль), парно по картам;
  - G0 — у кандидата 0 сбоев;
  - G1 — прямой матч, нижняя граница CI для S > 0.50;
  - G2 — Δ против `boss` ≥ −2 pp;
  - G3 — Δ против `old` ≥ −2 pp, пока `old` нет — пропуск записывается;
  - точечный фикс (меняет < 10 % карт): G0, S ≥ 0.500, Δ против `boss` ≥ −1 pp и регрессионный тест;
  - инструмент — `tools/bench_pair.py`.
- Размер серии / правило остановки и допустимое время эксперимента: 2000 карт внутри процесса (около 20 с) и 500 карт против внешнего процесса (около 2 мин). Без досрочной остановки и без продления. Репликация на новом блоке нужна, только если на одном блоке проверялось несколько вариантов.
- Правила учёта ничьих, ошибок, нелегальных ходов и таймаутов:
  - ничья = ½, число ничьих отчитывается;
  - любой сбой кандидата (ошибка, таймаут, медленный ход, лишняя строка) проваливает G0;
  - если сбой у соперника или контроля, карта исключается из обоих плеч; исключено больше 1 % карт — серия недействительна.
