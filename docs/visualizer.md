# Дашборд игр и просмотр реплеев

Приложение помогает выбрать интересные аренные игры по общей статистике, запускать одиночные
локальные матчи и разбирать реплеи на поле. Арена использует сохранённые данные проекта;
приложение не обращается к CodinGame.

## Запуск

Из корня репозитория:

```powershell
./gradlew.bat serve
```

Откройте [дашборд](http://localhost:8765/visualizer/). Сервер слушает только localhost.
Он работает, пока запущена команда; остановка — Ctrl+C. Другой порт задаётся через `-Pport=8766`.

## Локальные игры

В верхней навигации выберите «Локальные игры». Укажите ботов для сторон 1 и 2, при необходимости
поменяйте их местами и нажмите кнопку запуска. Можно выбрать замороженные v00–v04 или текущий
код `current`. Для каждой стороны с `current` отдельно доступны переключатели поддерживаемых
текущей сборкой параметров:

- `UNSTICK` — обход, когда прямое движение к площадке почти остановилось; по умолчанию включён,
  при включённом `ROUTE` не действует.
- `APPROACH` — выбор точки касания на последнем шаге с учётом следующей площадки; по умолчанию выключен,
  при включённом `ROUTE` не действует.
- `ROUTE` — планирование маршрута до выбранной площадки с заблаговременным обходом препятствий;
  по умолчанию включён (с v04); появляется только в сборках бота с таким параметром.

Исходные значения берутся из параметров текущего кода. В этой ветке доступны
`UNSTICK=1, APPROACH=0, ROUTE=1`. Список разрешённых
переключателей задан сервером: произвольные параметры через форму передать нельзя.
Выбор в форме действует только на запускаемый матч, не меняя умолчания бота или замороженные версии.
Можно поставить `current` с разными флагами на обе стороны. Для v00–v04 переключатели скрыты и
не передаются серверу. Кнопка обмена сторонами переносит бота вместе с его флагами; настройки и seed
сохраняются при перезагрузке страницы и в её адресе. При возврате с замороженного бота на `current`
сохраняется прежний выбор флагов этой стороны.

Seed задаёт карту: одинаковое число позволяет повторить ту же карту. Пустое поле выбирает случайный
seed. Для пробных игр через интерфейс используется диапазон 0–199999, чтобы не расходовать карты
для свежих проверок силы. Запускается один матч, а не серия сравнения; его исход сам по себе не
доказывает превосходство версии. Лимит 50 мс для встроенных ботов измеряется локальным раннером,
но не прерывает их ход: строгие проверки времени отдельного процесса остаются задачей `procCheck`.

После окончания матч сохраняется и сразу открывается в плеере. История локальных игр доступна
после перезапуска сервера; из реплея можно вернуться к списку или перейти к соседней игре.
Список можно отфильтровать по участвующему боту: `current · любые настройки` объединяет его
конфигурации, а варианты с перечисленными флагами показывают точную сохранённую конфигурацию.
В истории и карточках плеера видны настройки каждой стороны. Аренные фильтры и статистика ведутся отдельно.

Хранение — по **упорядоченной паре конфигураций**: первый в имени папки играет за сторону 1, второй — за
сторону 2. Например, `replays/local/v03-vs-v02/` и `replays/local/v02-vs-v03/` — разные папки.
У `current` в имени папки перечислены все доступные флаги с их значениями: матч с включённым
`UNSTICK` и выключенными `APPROACH` и `ROUTE` против v03 попадёт в
`replays/local/current-unstick1-approach0-route0-vs-v03/`. В отображаемом имени бота перечислены
только включённые флаги, например `current [UNSTICK=1]`; при всех выключенных — `current`.
В имени файла — время запуска UTC с миллисекундами и seed, например
`20261031T103302644Z-seed-42.json`. Если имя уже занято, добавляется короткий номер `-2`, `-3` и далее;
предыдущая игра не перезаписывается. Каждый JSON содержит полный реплей, результат, параметры
обоих ботов и сведения о сборке. Для `current` это особенно важно: его код со временем меняется,
поэтому одинаковое имя папки не означает одинаковый код.

Новые записи имеют `localGameVersion: 2`. В `botIds` хранится базовый бот (`current`, `v03` и т. д.),
в `botConfigIds` — каноническая конфигурация для папки и точного фильтра; `botFlags` хранит выбранные
булевы значения, `botSpecs` — переданные раннеру спеки, `effectiveParams` — полные действующие параметры.
Подписи сторон записаны в `bots`, сведения о скомпилированных классах и ресурсах сервера — в `provenance`.

Используется скомпилированный код запущенного сервера. После изменения Java-кода остановите сервер
и снова выполните `./gradlew.bat serve`; эта команда сначала компилирует изменения. Если классы
перекомпилированы при работающем сервере, новый матч потребует его перезапуска.
Для сохранённого реплея повторная компиляция не нужна — плеер читает уже записанные кадры.

Старые файлы в `build/replays/local/` по-прежнему открываются прямой ссылкой. Они автоматически
не переносятся в новую историю. Отчёты серий в `replays/bench/` остаются отдельными результатами
экспериментов; интерфейс одиночных игр их не заменяет.

## Выбор игр

Сверху находятся общие фильтры: версия, лига, загрузка, результат, сторона, соперник и номер игры.
По умолчанию выбраны последняя зарегистрированная версия проекта, её лига и все её загрузки.
«Все версии проекта» не включает старого бота; для него есть отдельный вариант «Старый бот».
В одном представлении всегда одна лига: показатели разных лиг не объединяются.

Списки выбора применяются сразу. Поиск по нику и номеру игры применяется кнопкой «Найти» или Enter.
«Сбросить» возвращает исходную выборку. Кнопка обновления перечитывает локальные манифесты после
нового скачивания игр.

Фильтры действуют на три вкладки:

- **Обзор** — количество игр, побед, поражений, доля побед, результаты по сторонам и отдельным
  загрузкам. Нажатие на показатель открывает соответствующие игры. Короткий список соперников
  с наибольшим числом наших поражений ведёт к встречам с выбранным игроком.
- **Соперники** — встречи, победы, поражения, ничьи и наша доля побед против каждого игрока.
  Можно задать минимальное число встреч и сортировать по числу поражений, их доле или числу игр.
  Нажатие на ник открывает точную выборку этого соперника. Встречи сгруппированы по нику; код
  соперника мог меняться между его загрузками.
- **Игры** — список с результатом, итоговыми HP, стороной, версией, загрузкой и соперником.
  Доступны сортировка и страницы. Кнопка «Смотреть» открывает реплей.

Доля побед — число побед, делённое на число всех игр в выборке; ничьи показаны отдельно.
На широком экране фильтры и вкладки остаются видимыми, а длинные таблицы прокручиваются внутри
своих панелей. Возврат из реплея восстанавливает и положение прокрутки списка.
Сводки описывают сохранённые игры, а не оценивают силу бота. Всегда учитывайте число встреч:
одного поражения недостаточно, чтобы считать соперника устойчиво неудобным. Состав соперников
между загрузками различается.

Исход определяется по местам CodinGame, в том числе когда итоговые HP одинаковы. Значение −1
в исходном счёте означает снятие игрока и отображается как «снятие», а не как отрицательные HP.
Такие игры входят в результаты, и их можно выбрать отдельным фильтром. Рейтинг соперника взят
на момент скачивания, не обязательно на момент боя. Длительность в списке приблизительна по
числу кадров; в просмотрщике используются ходы из самой записи.

## Просмотр игры

На поле показаны записанные положения королев, юнитов и построек. Рядом — состояние игроков,
команды и сообщения игры. Нажмите на объект, чтобы посмотреть его характеристики.

«Цели команд» включены по умолчанию и показывают команду следующего записанного хода: пунктир
идёт от текущей позиции королевы к центру площадки для `BUILD` или к записанным координатам для
`MOVE`. В карточках основным текстом показаны команды текущего, уже завершившегося хода; ниже
серым — команды следующего хода, которым соответствуют линии. На старте вместо текущих команд
показано «Начальное состояние». На последнем кадре цели скрыты, а строка следующего хода содержит
«Конец записи». Сообщения игры относятся к уже завершившемуся ходу, его номер указан отдельно.
Линия сохраняется до полной цели команды. Только для `MOVE` показаны два круга радиуса 30:
пунктирный в цвете стороны — шаг до 60 единиц по этой прямой без столкновений, сплошной зелёный —
фактическая позиция королевы в следующем кадре реплея. Для близкой цели прямой шаг заканчивается
в самой цели. При совпадении позиций зелёный контур виден между штрихами пунктира.
Для `BUILD` и `WAIT` эти круги не показываются.

Для перемещения по записи есть ползунок, выбор хода, воспроизведение и скорость.
Скорость выбирается из 0.5x, 1x, 2x, 5x, 10x и 20x; 1x — один ход каждые 250 мс.
Кнопки со значками шага переключают ходы; значки воспроизведения/паузы меняются по состоянию.
Подсказки кнопок показывают действие и клавишу. Стрелки клавиатуры
переключают ходы, пробел ставит запись на паузу или продолжает её. «Старт» — исходное состояние;
следующие кадры показывают состояние после соответствующего хода.

На компьютере поле и управление помещаются по высоте окна; справа находятся компактные карточки
игроков с командами, сведения о выбранном объекте и сообщения. Ники выделены цветом стороны.
Длинные команды и сообщения прокручиваются внутри блоков; при необходимости прокручивается
вся боковая колонка. Когда фокус клавиатуры в этой колонке, стрелки и пробел прокручивают её,
не переключая ходы. На узком экране карточки располагаются под полем, доступна прокрутка страницы.

«Предыдущая игра» и «Следующая игра» проходят по **всей текущей выборке в выбранном порядке**, а не
только по странице списка. «К выборке» возвращает к прежней вкладке, фильтрам, сортировке и странице.
Работают также кнопки браузера «Назад» и «Вперёд». Выборка, открытая игра и ход сохраняются в адресе:
его можно скопировать, чтобы снова открыть тот же разбор на этом компьютере при работающем сервере.

Арена воспроизводится по сохранённым событиям CodinGame: текущий бот и локальный симулятор
не запускаются. В записи видно, обучает ли барак войска, но точное число оставшихся ходов не
передаётся; просмотрщик показывает «идёт обучение» без выдуманного отсчёта. Для локальных реплеев
доступный в них отсчёт сохраняется.

Прежние прямые ссылки на локальные игры работают:

```text
http://localhost:8765/visualizer/index.html?file=/build/replays/local/<имя>.json
```

Отдельный реплей открывается без последовательного перехода по аренной выборке.

## Данные и сообщения об ошибках

Каталог читает реестр `docs/data/arena-uploads.json` и указанные в нём манифесты игр. Сам файл
реплея из `rawDirectory` загружается только при открытии игры. Размещение файлов и команды
скачивания описаны в [arena-uploads.md](arena-uploads.md#replay-storage).

Если манифест недоступен или принадлежит другому агенту, дашборд явно сообщает, что каталог
загружен не полностью. Его показатели тогда относятся только к доступным играм. Неудачные
скачивания из манифестов тоже обозначаются. Если отсутствует или повреждён сам реплей, появляется
сообщение об ошибке; выборка сохраняется, и можно вернуться к списку или повторить открытие.

## Проверки разработки

Из корня репозитория:

```powershell
node --test visualizer/tests/catalog.test.mjs visualizer/tests/local.test.mjs visualizer/tests/player.test.mjs
./gradlew.bat test --tests cr.tools.CgViewReplayTest --tests cr.tools.ServeTest --tests cr.tools.LocalGamesTest
```

Первый набор проверяет каталог, фильтры, расчёт результатов и состояние локальной страницы.
Второй — разбор записанных состояний, сервер, запуск и сохранение матча, историю после перезапуска,
обработку неверных запросов и защиту путей сохранения. Проверки интерфейса и результаты выполненных
прогонов находятся в `docs/DEVLOG.md`.
