Архитектура текущего бота

Бот жадный и без поиска. Каждый ход он смотрит только на текущее состояние и проходит фиксированную лестницу правил. Сначала один барак рыцарей, потом шахты до дохода 3, потом до 8 башен. Если рядом вражеские рыцари, королева бежит к своей башне. Все бараки, на которые хватает золота, тренируют каждый ход.

Состояние между ходами — только две вещи: сторона старта (homeLeft) и план обхода UNSTICK. Дедлайн передаётся в play, но не читается: бюджет 50 ms бот не использует.

Страница описывает код на коммите 18b8311 и лежит в репозитории как docs/bot-architecture.html, рядом — английская текстовая версия docs/bot-architecture.md. При изменении правил в MainBot.play обе нужно обновить.

Один ход: от stdin до stdout

На CodinGame всё склеено в один Player.java (FileMerger). Точка входа — CGRunner.main. Локальный referee и бенч зовут тот же MainBot.play внутри процесса, так что логика бота одна и та же.

  1. stdingold, touchedSite, сайты, юниты
  2. InputReaderразбор ввода; игрок 0 = я
  3. GameStateмассивы сайтов и крипов
  4. MainBot.playправила → Command
  5. stdoutстрока 1: WAIT, MOVE или BUILD; строка 2: TRAIN

Что делает раннер вокруг бота

  • Init. Читает сайты; золото неизвестных сайтов оценивается как 225, maxMineSize как 2, пока королева не увидит реальные значения.
  • Ход 0, прогрев. До 300 ms бот-одноразка играет на изменённых копиях состояния (касание сайта, бегство от рыцаря, все башни свои), чтобы загрузка классов и лямбд прошла в 1000-мс ходу, а не в 50-мс.
  • Ход 0, метка. Если TRAIN пустой, вместо него печатается build id: 8 hex-цифр как id сайтов. Referee ругается «not a barracks» и ничего не делает, а метка остаётся в реплее.
  • Защита. Любое исключение в play даёт WAIT + пустой TRAIN. Ход дольше бюджета пишет SLOW turn в stderr.

Решение королевы

Правила проверяются сверху вниз; первое сработавшее даёт команду. «Угроза» — число вражеских рыцарей ближе 250 к королеве.

к королеве; без башен MOVE домой"]

к середине пути к дому;

к дому; без башен MOVE домой"]

Лестница: нет барака → BARRACKS-KNIGHT; доход ниже 3, на сайте есть золото и нет угрозы → MINE; башен меньше 8 → TOWER. Если правило касания не дало команды (чужой сайт, шахта на максимуме, угроза мешает шахте, лестница выполнена), решение уходит ниже, к угрозе. Рыцари врага — единственная угроза, которую бот видит; лучники и гиганты не считаются.

Что легко упустить

  • Правила касания не смотрят на лестницу. Если рыцари не помешают, каждая построенная шахта прокачивается до максимума, поэтому доход может превысить INCOME_TARGET. Каждая новая башня подкачивается (+100 HP за BUILD), пока у неё не станет хотя бы 700 HP.
  • Угроза останавливает на сайте касания только шахту: барак и башню королева всё равно строит, а бегство идёт после них.
  • Когда лестница выполнена (или подходящих сайтов не осталось), королева стоит у своей башни возле дома и строит её снова и снова.

Псевдокод

Сжатый пересказ MainBot.play. Значения параметров — v03.

play(state, touched):
    income  = Σ rate своих шахт
    barracks, towers = число своих бараков, башен
    home    = угол старта: (0,0) или (1920,1000)
    threat  = #{ вражеский рыцарь : dist(рыцарь, королева) < 250 }

    // 1. Касаюсь сайта — действую на месте
    if touched ≥ 0 and not underEnemyTower(touched):
        if своя шахта and rate < maxMineSize and threat == 0: cmd = BUILD touched MINE
        elif своя башня and hp < 700:                       cmd = BUILD touched TOWER
        elif сайт пустой:
            if   barracks < BARRACKS(1):                         cmd = BUILD touched BARRACKS-KNIGHT
            elif income < INCOME_TARGET(3) and gold > 0 and threat == 0:
                                                              cmd = BUILD touched MINE
            elif towers < MAX_TOWERS(8):                       cmd = BUILD touched TOWER

    // 2. Бегство
    if cmd == null and threat > 0:
        tw  = своя башня, ближайшая к королеве
        cmd = tw ? BUILD tw TOWER : MOVE home

    // 3. Идти к следующему сайту
    if cmd == null:
        if лестница не выполнена:
            target = argmin dist(site, (queen + home) / 2)
                     среди пустых сайтов не под вражеской башней
                     (пока строим шахты — только с золотом > 0)
        if target:
            cmd = BUILD target (BARRACKS-KNIGHT | MINE | TOWER по лестнице)
            if UNSTICK: cmd = unstick(cmd)     // может стать MOVE в обход
        else:
            tw  = своя башня, ближайшая к дому
            cmd = tw ? BUILD tw TOWER : MOVE home

    // 4. Тренировка: жадно, по порядку id
    for барак in свои бараки (не тренирующие):
        if gold ≥ цена: gold -= цена; train += барак

    return cmd + TRAIN train

Выбор цели на карте

Цель — пустой сайт, ближайший не к королеве, а к середине отрезка «королева → домашний угол». Так стройка тянется к своему углу, и база получается компактной: бараки, шахты и башни рядом, бегство короткое. Сайты под вражеской башней (центр сайта в радиусе башни) пропускаются.

Схема, не масштаб. Сайт за вражеской башней отброшен, барак уже свой, из пустых ближе всего к жёлтой точке — обведённый.

UNSTICK: обход застревания

BUILD ведёт королеву прямо к центру сайта. Если по прямой стоит другой сайт, коллизия отталкивает её назад, и она стоит на месте (в v01 до 43 ходов). UNSTICK срабатывает только для BUILD к следующей цели, не для бегства.

  1. Продолжить начатый обходЕсли в прошлый ход был обход к этому же сайту и ходы обхода остались, сделать ещё один MOVE тем же курсом, если он сдвигает королеву хотя бы на 2.
  2. Проверить прямой шагPhysics.queenStep предсказывает шаг: скорость 60, 5 проходов коллизий, только сайты, без юнитов. Если шаг сдвигает королеву или она начинает касаться сайта, остаётся обычный BUILD.
  3. Перебрать курсы24 курса: отклонение ±15°, ±30°, … ±180° от прямой. По каждому 1–6 ходов MOVE, затем прямая до касания (горизонт 25 ходов).
  4. Выбрать лучшийМеньше всего ходов до касания; при равенстве — меньший угол, +15° раньше −15°, меньше ходов MOVE. Сделать первый MOVE, остальные запомнить.

MOVE ставится на 200 вперёд по курсу и обрезается краем поля. Если ни один план не находит касания, остаётся BUILD.

TRAIN

Каждый ход перебираются свои бараки по возрастанию id. Барак, который не тренирует и на который хватает золота, тренирует; золото уменьшается. Барак у бота один и только рыцарский: 4 рыцаря за 80 золота, 5 ходов. Лимит 30 крипов на игрока не проверяется: это важно только при нескольких бараках.

Чего бот не делает

Это прямо следует из кода; что из этого стоит сил, решают эксперименты по P2.

  • Не смотрит вперёд: нет симуляции ходов, хотя полный симулятор (Rules) сверен с реплеями и даже входит в артефакт.
  • Строит только рыцарей и один барак. Нет лучников против рыцарей и гигантов против башен.
  • Видит угрозу только от рыцарей ближе 250. Не реагирует на вражеских гигантов у своих башен.
  • Не целится во вражеские шахты и бараки: королева сносит их простым касанием, но целью выбирает только пустые сайты.
  • Не думает о своей атаке: рыцари идут к королеве врага сами, бот не выбирает момент и не копит золото на волну.
  • После лестницы плана нет: королева стоит у башни возле дома и строит её снова и снова.
  • Не проверяет лимит 30 крипов (важно только при нескольких бараках) и не использует бюджет времени.
